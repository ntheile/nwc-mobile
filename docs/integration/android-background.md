# Android background execution

The Android integration uses FCM for routing and WorkManager for durable
background execution. Kotlin owns Android lifecycle mechanics; Rust owns Nostr
validation, authorization, replay protection, payment policy, and responses.

Use the [`android/nwc-mobile`](../../android/nwc-mobile/README.md) package rather
than creating a second scheduler or retry state machine.

## FCM handoff

The wallet owns `FirebaseMessagingService`. Its callback should immediately
pass `RemoteMessage.data` to `NwcWorkManagerWakeScheduler` and return:

```kotlin
class WalletMessagingService : FirebaseMessagingService() {
  override fun onMessageReceived(message: RemoteMessage) {
    NwcWorkManagerWakeScheduler(
      WorkManager.getInstance(applicationContext),
      WalletNwcWakeWorker::class.java,
    ).schedule(message.data)
  }
}
```

The scheduler validates transport bounds, creates unique network-constrained
work, and stores only required routing fields. Embedded encrypted event content
is deliberately omitted from WorkManager storage; Rust can fetch the exact
event from an approved relay.

## Worker bridge

Subclass `NwcWakeWorker` and supply:

- an `NwcWakeExecutor` that enters the generated Rust API; and
- a thread-safe, idempotent cancellation bridge.

```kotlin
class WalletNwcWakeWorker(
  context: Context,
  parameters: WorkerParameters,
) : NwcWakeWorker(context, parameters) {
  override val executionMilliseconds = WALLET_BACKGROUND_WINDOW_MS

  override fun createExecutor(): NwcWakeExecutor = WalletRustWakeExecutor()

  override fun createCancellation(): NwcWakeCancellation =
    WalletRustCancellation()
}
```

The worker maps only stable Rust dispositions:

- completed or already processed -> WorkManager success;
- explicitly retryable -> WorkManager retry;
- application handoff -> the wallet's bounded recovery path; and
- terminal rejection -> WorkManager success without repeating invalid work.

Do not infer retryability from exception strings.

## Storage and wallet opening

The worker may run in a newly created application process. Its Rust adapter must
resolve the same application data directory and Keystore-backed secrets as the
foreground application, then use `LightningNodeProvider` to open the existing
wallet.

Do not store a foreground wallet pointer, activity, view model, invoice, or
secret in WorkManager input data. Work names and tags should contain only the
shared digest-based identifier generated by the helper.

## Maintenance

Use `NwcWorkManagerMaintenanceScheduler` and `NwcMaintenanceWorker` for:

- unresolved payment reconciliation;
- pending wake registration or unregistration; and
- recovery after an interrupted ordinary wake.

Maintenance work contains no NWC request payload. It is unique and
network-constrained, and cancellation must immediately propagate to Rust.

## FCM payload

The recognized routing fields match the Apple payload:

- `nwc_relay`;
- `nwc_event_id`;
- `nwc_wallet_service_pubkey`; and
- optional bounded `nwc_event_json`, which is not copied to WorkManager.

Never include secret material, a complete NWC URI, decrypted request, invoice,
amount, counterparty, or raw error text.

## Device testing

Test on physical devices across:

- foreground, background, and OS-killed process states;
- process recreation before worker execution;
- network loss and WorkManager retry;
- battery optimization and Doze; and
- cancellation during wallet opening and payment reconciliation.

Android's user-initiated force-stop prevents FCM and WorkManager delivery until
the user launches the application again. Treat that as a platform limitation,
not a retry state the library can bypass.

See [Testing an integration](../testing.md).
